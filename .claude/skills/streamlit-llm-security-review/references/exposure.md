# 観点 2: 公開範囲・起動設定

「ローカル専用アプリ」と説明されていても、実際にローカル専用として動いている保証はない。
コードの外側（起動コマンド・設定ファイル・ファイル権限）にリスクが出るため、
コードだけを読んでいると丸ごと見落とす。

この観点の指摘は、**修正が 1〜2 行で済むのに効果が大きい**ものが多い。優先して見る。

## 2.1 待ち受けアドレス（この観点の本命）

Streamlit は `server.address` を設定しない限り、全インターフェースで待ち受ける。
つまり `localhost:8501` のつもりでも、同じ Wi-Fi にいる他人が
`http://<あなたのIP>:8501` で開ける。

そこで何が起きるか、を具体的に書くこと。**開かれた時点で API キーは既にアプリに
読み込まれている**（環境変数や `.env` から）ので、他人はキーを見ることなく、
持ち主の課金で生成し放題になる。要約タブがあれば、そこに貼られた内容も見える。

確認手順:

1. `.streamlit/config.toml` に `[server] address` の指定があるか
2. 起動コマンド（README・スクリプト・`Makefile`）に `--server.address` があるか
3. 実際に起動中なら、待ち受けアドレスを直接見る

   ```bash
   lsof -nP -iTCP:8501 -sTCP:LISTEN
   ```

   `*:8501` なら全インターフェース、`127.0.0.1:8501` ならローカルのみ。

いずれの指定もなく、設計上ローカル専用なら **高**（同一ネットワークからキーを使われる）。
ただし、そのマシンが自宅の閉じたネットワークにしかつながらないと分かっている場合は
中に落としてよい。前提に照らして決める。

修正案:

```toml
# .streamlit/config.toml
[server]
address = "127.0.0.1"
```

README の起動コマンドも合わせて直す（設定ファイルだけ直しても、README を見た人が
別の起動方法を使えば元に戻る）。

## 2.2 XSRF / CORS

- `server.enableXsrfProtection = false` になっていないか。既定は true。
  ネット上の記事では「アップロードがうまくいかないときは false にする」と書かれがちで、
  そのままコピーされていることがある → **中**
- `server.enableCORS = false` も同様に確認する
- これらを false にする必要が本当にあるなら、代わりに待ち受けアドレスを絞る提案をする

## 2.3 ファイル権限

同じマシンに他のユーザーアカウントがある場合、または貸し借りするマシンの場合に効く。

```bash
ls -l .env .streamlit/secrets.toml 2>/dev/null
```

- `.env` / `secrets.toml` が `644`（他ユーザーが読める）→ **中**。`600` を推奨
- 修正案: `chmod 600 .env`

## 2.4 `.streamlit/secrets.toml`

Streamlit 固有の秘密情報ファイル。存在する場合:

- `.gitignore` に入っているか（`.streamlit/secrets.toml` は入れ忘れが多い）
- パーミッションは 2.3 と同じ基準
- `.env` と二重管理になっていないか（どちらが実際に使われているか分からない状態は、
  片方だけ対策して安心する事故につながる）

## 2.5 「ローカル専用」と矛盾する痕跡

設計はローカル専用なのに、公開前提の仕組みが混ざっていないか探す。混ざっていたら、
前提そのものが崩れているので、他のすべての深刻度を見直す必要がある。

- `--server.headless true` や `server.port` を外部向けに変えている
- ngrok / cloudflared / localtunnel の設定や手順が残っている
- Streamlit Community Cloud / Hugging Face Spaces へのデプロイ設定
  （`packages.txt`、`.streamlit/config.toml` の `[global]`、デプロイ用ワークフロー）
- Dockerfile で `0.0.0.0` を明示している

公開ホスティングに載せる前提が少しでもあるなら、
**環境変数にキーを置く前提そのものを見直す必要がある**と書く。
ホスティング先で認証なしに公開されれば、待ち受けアドレスの話ではなく
「世界中の誰でもキーを使える」状態になる。

## 2.6 運用上の残留

- 起動しっぱなしのプロセスを止める手順が README にあるか
  （`lsof -ti:8501 | xargs kill` など）。ノート PC を持ち歩いたまま
  アプリが動き続けていると、2.1 の問題が外出先で発現する → **低**
- 生成結果の出力ディレクトリ（`outputs/` など）が `.gitignore` に入っているか
